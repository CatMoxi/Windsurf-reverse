# Language Server Launch Protocol

## Complete reverse-engineered startup sequence

### 1. Extension generates CSRF token

```javascript
// ExtensionServer constructor receives csrfToken as first parameter
// csrfToken is generated elsewhere and passed via A.csrfToken in the config object
// This token is also set as env var: WINDSURF_CSRF_TOKEN
```

### 2. ExtensionServer starts (before LS)

```javascript
// ExtensionServer listens on random port (127.0.0.1:0)
// Provides Connect-RPC services back to the LS
// The port is passed as --extension_server_port to LS
const server = http.createServer();
server.listen(0, "127.0.0.1");
// Validates CSRF token on every incoming request:
// e.headers["x-codeium-csrf-token"] === this.csrfToken
```

### 4. Environment Variables

```bash
CODEIUM_EDITOR_APP_ROOT=<appRoot>     # Path to VS Code app root
WINDSURF_CSRF_TOKEN=<csrfToken>       # CSRF token for ExtensionServer auth
# Plus: all proxy env vars from system
# Plus: any custom languageServerEnv from config
# Insiders only: GORACE=halt_on_error=1
```

### 5. Initial Metadata via stdin

After spawning, the extension writes serialized metadata (protobuf binary) to stdin:

```javascript
const metadata = MetadataProvider.getInstance().getMetadata();
if (metadata.apiKey) {
  const binary = metadata.toBinary();
  process.stdin.write(binary);
}
process.stdin.end();
```

This is a `Metadata` protobuf message containing the API key and other auth info.

### 6. Named Pipe for Parent Communication

The extension creates a named pipe:
- **Windows**: `\\.\pipe\server_<random_hex>`
- **Linux/Mac**: `/tmp/server_<random_hex>`

This pipe path is passed via `--parent_pipe_path` and is used for:
- Process health monitoring
- Graceful shutdown signaling

### 7. LS Startup Callback

Once started, the LS calls back to ExtensionServer:
```
ExtensionServerService/LanguageServerStarted
```

This resolves `waitForLanguageServerStart()` in the extension, which has a 60s timeout.

### 8. Connect-RPC Client Creation

After receiving the LanguageServerStarted callback:
```javascript
// Extension creates Connect-RPC client pointing to the LS port
// All subsequent RPCs go through this client with CSRF token header
// Header: x-codeium-csrf-token: <csrfToken>
```

### 9. Error Handling

- Stderr is captured and buffered (up to 1MB)
- On exit, goroutine logs are saved
- Crash detection and restart logic exists

## Key Security Model

1. **CSRF Token**: Random token shared between extension and LS
   - Generated by extension
   - Passed to LS via env var `WINDSURF_CSRF_TOKEN`
   - Required on every RPC call as header `x-codeium-csrf-token`
   - NOT the same as the API key

2. **API Key**: Sent via stdin at startup (protobuf encoded)
   - Used for authentication with server.codeium.com

3. **Named Pipe**: Parent-child IPC channel
   - Used for health monitoring, not for RPC traffic

4. **Localhost-only binding**: Both LS and ExtensionServer bind to 127.0.0.1
